- 2026-07-12 (M8): behaviour-preserving SEM refactors are fenced by two byte-pinned guardrails — the `exp_strict_*` syntax snapshots (`test-ssm_sem_syntax.R`) and the `summary()` label strings (tabs/casing) — so DRY extraction there is safe to verify by "existing suite stays green". - 2026-07-12 (M9): vectorizing `sem_estimate()`'s per-draw transform loop needed NO re-pins — keep the tested scalar `sem_ssm_transform()` as the reference and pin the matrix pass to it row-by-row (incl. the §5.5 flat/zero-amplitude NA semantics); `rowMeans`/matmul FP reorder stays within existing tolerances. `sem_pop()`-composing `make_pop_2g()` was bit-identical (same op sequence), so re-recording the coverage rds is a deterministic no-op — verify by `identical()` instead of an expensive stochastic rerun.
- 2026-07-12 (M11): mechanical test-fixture rewrites must be validated with `devtools::check()`, not just `devtools::test()`/`load_all()`. Consolidating inline populations into a `sem_canonical_pop()` helper removed a block's `a`/`cc` locals it still used to rebuild `lambda1`; `test()`/`test_file()` under `load_all()` **masked** the `object 'a' not found` (an earlier block's `a` leaked into scope), and only the clean-env R CMD `check()` caught it. Also: the four SSM boundary invariants were already covered at the bootstrap/montecarlo/ci_accuracy/SEM entry points — the real gaps were the *correlation* path's flat and pole corners; audit before writing a "new" boundary suite (`cairn/boundary-coverage.md` is the standing matrix).
- 2026-07-12 (M12): when DRY-extracting a Label/Group/Measure builder, swapping `cbind(Label, Group, Measure, df)` (vectors + df) for `cbind(labels_df, df)` (df + df) is byte-identical in R ≥ 4.0 — same column names, character (not factor) types, and row names — provided the helper builds its data.frame with `stringsAsFactors = FALSE`. Verify by `identical()` on both the default and non-default (contrast) row-name cases, not just value equality; the byte-pinned end-to-end snapshot/label tests are the oracle (no separate statistical oracle needed for a behaviour-preserving label refactor).
- 2026-07-12 (M10): `cairn_validate.py`'s ISO-date check flags any `\d+/\d+/\d+` token as a malformed date — writing a `check()` result as "0/0/0" in a tracking file trips it. Write "0 errors / 0 warnings / 0 notes" (spaces around slashes) instead. Also: when a milestone Goal names a function family but the enumerated Scope/Tasks list specific sites, grep the whole family first — the plan's site list drifts (post-merge line shifts) and can silently omit members (M10 missed `ssm_analyze()`'s own validators; the two-lens review caught it).
- 2026-07-12 (M13): a regression-guard test that **re-types** the production expression instead of calling the production code path has NO teeth — the review (F1) caught a "CPM angle-CI oracle" whose end-to-end fixture never straddled the pole, so a linearized `cpm_fit.R:1119` passed it. Prove a guard bites by breaking the guarded line (`assignInNamespace` a linearized `quantile.circumplex_radian`) and confirming red. To force a deterministic 0/360 straddle through `cpm_fit()`: put a *non-reference* item exactly on the pole, sample raw data via `cpm_implied_cor()`+`chol()`+`rnorm()` (seeded, base-R, no MASS), and assert the reported CI **wraps** (`Angle_lci > Angle_uci`) — a linear quantile yields a ~357° non-wrapped span instead. Such a bootstrap+optimization test is deterministic given the seed and (large-margin wrap) robust enough to run in CI under `skip_on_cran()` alone; Windows CI green confirmed no BLAS flip.
