- 2026-07-12/18/19 (M13, M33, M35, M40, M43): **a guard has teeth only if you break the guarded line and see it fail.** Five silent failures: (a) the test re-types the production expression instead of calling the code path (M13 — fixture never straddled the pole; force a wrap with an item exactly on the pole, assert `Angle_lci > Angle_uci`); (b) the assertion is arithmetically implied by the defect (M33 — `expect_true(all(uci - lci < 180))` is guaranteed by the clamping it should catch; assert width EQUALS `ssm_arc_span(lci, uci)`); (c) the fixture hits the regime where the bug is invisible (M35 — a wide arc CENTRED on its estimate reproduces the right width by symmetry; place the estimate off-centre); (d) the guard never matched at all (M40 — `cairn_validate`'s INDEX parser reads the first `.md` token after the bullet, so bare-citekey link TEXT is silently not a catalog entry; use the filename); (e) the PROBE was narrower than what it probed (M43 — `pdftotext -layout` splits a display equation across lines, `(N)` marker alone, so a grep pinned to the marker line reads as "equation missing"; that false claim reached a provenance block before review re-ran the command). (f) **the probe's own syntax lied (M57, six times in one milestone): a whole-file `grep` credited surface A with text that lives in surface B; `-0.01\b` matched the very note that states the rule; an unescaped `$` in a BRE acted as an end-of-line anchor; a containment `grep -q` inside a line range stood in for checking its boundaries (shipping an off-by-one anchor into a provenance block); and twice a single-line pattern missed text roxygen had wrapped across lines. Scope the probe to the thing probed, use `grep -F` for anything containing regex metacharacters, verify a range by its first AND last line, and flatten wrapped prose before matching it.** (g) **M59, three at once on one new input path: the guard checked fewer dimensions than the indexing used** (`colnames` validated while `m[rows, cols]` subset by both dimnames, so a colnames-only matrix — the shape `as.matrix(read.csv(...))` actually produces — reached a bare `subscript out of bounds`; the test probed `unname()`, BOTH absent, missing the half-present case users generate); **the mutation reddened for the wrong reason** (a permuted-input test asserted estimates lavaan makes invariant by matching `sample.cov` on dimnames itself — diff exactly 0 with the reorder removed — so it caught the mutant only through ~1e-8 optimizer jitter; assert the quantity the path actually determines, here `ols_shadow`, which collapses 600×); and **an absolute bound sat 3.8× from its threshold** where a comparative one ("the convention-matched pairing agrees WORSE") states the same claim and absorbs platform noise on both sides.** (h) **M61, the fixture itself was impossible: the AC2 "mixed map" test glued two independent `axes_simulate()` draws with `cbind()`, so NO population generated the matrix** (measured cross-block `cor = -0.017` against a model-implied ~0.19; the fit returned `zeta1 = 0.274` for a nominal `.08`) — and it passed, because it asserted only a row count, a boolean flag and some names. A structural-only assertion cannot notice that its own fixture is incoherent. Build the fixture from ONE population and assert the estimates land near its truth, so the fixture's validity is under test too. Prove by mutation, never by eye; never infer coverage from a probe that cannot see what it checks. Same shape at baseline level (M38): every vdiffr baseline used an `amax` the break generator already lands on, so a behavior change moved none of them -- a clean snapshot run is evidence only after checking the baselines exercise the CHANGED path, and the fix is to add a baseline, not to report the clean run. **(i) M62, the mock routed past the thing under test:** a test titled "raises no bare NaN warning" mocked the boundary predicate to `TRUE`, which routes to a literal `sem <- c(NA_real_, NA_real_)` -- the arithmetic that could raise the warning never ran, and both assertions were implied by that literal, so deleting the guard it nominally covered left it GREEN. A seam mock proves the BRANCH WIRING, never the CONDITION that selects the branch; assert the condition against the unmocked path, and let the mocked test's title claim only the wiring. **(j) M65, twice, both from a comparison that cannot fail: two sides built by the SAME line of code catch nothing common-mode.** `expect_identical(names(fi$fit), names(lw$fit))` compared two lists from one `fitMeasures()` call, and lavaan DROPS an unrecognized measure name (shorter vector, no error) -- so a renamed name shortens both sides alike, the comparison passes, `$fit$srmr` silently vanishes from a documented `@return`, and `expect_equal(fi$fit$srmr, lw$fit$srmr)` degenerates to `expect_equal(NULL, NULL)`, which passes too. Pin one side to a LITERAL. Same milestone, same shape in a predicate: `grepl("moments using EM", msg, fixed = TRUE)` never fired on either lavaan generation, because lavaan wraps its warnings at `getOption("width")` and the literal straddles the newline -- a two-disjunct safety predicate had silently been a one-disjunct one through three review passes. Never match a dependency's message text with `fixed = TRUE` across a word boundary; allow `[[:space:]]+`, and dump `conditionMessage()` with `dput()` before writing the pattern.
- 2026-07-13 (M18): when a milestone changes a return value's *semantics*, the bug lives in the CONSUMERS, not the diff — `cpm_fit()`'s `matrices$Phat` went correlation→covariance under `scaling="free"` and `ssm_ci_accuracy(cpm=)` silently embedded the non-unit diagonal into a correlation population. Grep every consumer of a changed field and guard the ones assuming the old invariant — refuse the unsupported combination with a clear message + regression test, never silently coerce.
- 2026-07-16/18 (M21, M34): **anything run outside `devtools::load_all()` reads the INSTALLED package, not the dev tree.** A standalone `rmarkdown::render()` of a dev-line vignette fails spuriously at an innocent chunk (`devtools::check()` is the authoritative vignette build); a bare `Rscript -e 'library(circumplex); getNamespaceExports(...)'` audited 29 exports instead of the dev tree's 43. Run introspection under `load_all()` and print `packageVersion()` to prove which tree answered.
- 2026-07-16 (M20): the 0/360 pole's float label is platform- and path-dependent — R's `%%` clamps the fmod edge to exact 0 (macOS) while the C++ `modu` path yields exact 2π, and last-ulp libm variation leaves a pole residue a few ulp wide. Any pole-snap window must be ≥ a few ulp of 2π (M20: `16*eps` ≈ 4 ulp; a `2*eps` window is thinner than ONE ulp of 2π and catches only bit-exact 2π), and estimate-path boundary assertions follow G2's either-label rule — reserve `expect_identical(…, 360)` for value-level-snapped endpoint contracts, never values riding through libm trig.
- 2026-07-16 (M23): a spec's quantitative claims need the adversarial-derivation treatment code gets — "paired CIs are narrower at ρ>0" was false for Δa/Δd (delta-method cross term ∝ ρ·cos Δd; reverses past |Δd|=90°) and survived drafting; only independent derivation (RR06) caught it. Write efficiency/coverage claims as conditionals with the condition derived, and give the oracle a cell that EXPECTS the reversal. **M63 extends this to the CONDITION itself, which needs the same adversarial treatment as the measurements it rests on:** two block layouts were measured correctly (crossed → ξ1 unbiased, contiguous → +12%) and generalized into the shipped rule "blocks spread evenly around the circle are safe" — false, disproved by antipodal blocks whose angles average to the circle's centre yet bias ξ1 −9%. A test fencing two INSTANCES does not fence the condition: restating the rule wrongly reddened nothing until a counterexample layout was added. Same trap one level down: a worked example lifted from a test fixture inherits the fixture's parameters — "opposite-scale blocks are refused" held at the fixture's k=4 and was false at k=6/8/12, with 8 the package's canonical layout.
- 2026-07-16 (M25): an "independence baseline" for a MEAN-BASED estimator cannot be built by permuting rows within the drawn sample — group means are permutation-invariant, so estimates keep the paired sampling distribution while the engines see independent data. Draw the comparison arm from FRESH units; a reversal-expecting oracle cell (M23) is what exposed it.
- 2026-07-16 (M25): never resolve numeric column indices to names before subsetting a data.frame — `[.data.frame` resolves duplicated names to the FIRST match, so cbind-ed same-named blocks silently collapse onto block 1 (a wrong-answer channel, not an error). Subset by position and guard cross-block selections with an overlapping-columns error. Same family: positional info-column drops (`-c(1:3)`) break when a conditional column appears — drop by name.
- 2026-07-16 (M26): kernel bit-parity has two traps. R's `%%` is not C++ `modu()` at the pole — R applies a second reduction sending a tiny-negative angle to 0 where `modu()` gives 2π; wrap atan2 output with `d + 2*pi*(d < 0)`, never `%%`. And bit-exact oracle comparisons must compare values from the same single conversion expression — converting one side degrees→radians adds a rounding step and fails `expect_identical` by 1 ulp.
- 2026-07-17 (M28): collapsing a per-row long column by the first *physical* row (`col[match(ids, id)]`) silently discards a validated value when that row is NA — a covariate recorded only at a later wave becomes NA and the person is dropped by `ssm_analyze()`'s NA-grouping deletion. Take the first *non-NA* value per person (`split(seq_len(nrow), id_index)` → first non-NA row), indexing the original column so type is preserved. The round-trip-equivalence test missed it — its fixture had no NA-grouping cell. Pair any such reshape oracle with a "blank the first-occasion value, assert results unchanged" regression.
- 2026-07-17 (M29): a loose statistical assertion in a NEW diagnostic test can pass in isolation yet flake in the full suite — the object-building `ssm_analyze()` (bootstrap) inherits leaked cross-file RNG state, which for `ssm_ci_accuracy()` feeds near-zero/margin-rung detection via the stored `a_lci`/`a_uci`. Seed EVERY stochastic call including the `ssm_analyze()` that builds the object, and prove determinism under varied incoming RNG (`set.seed(x); runif(n)` before `test_file`), not standalone.
- 2026-07-17 (M29): to validate a plug-in coverage diagnostic, compare its REPORTED coverage to a direct Monte-Carlo of the REAL shipped procedure at the SAME plug-in (draw from the object's own μ̂/Σ̂, run `ssm_analyze()` per replicate, tally coverage of its own point estimates as fixed truth) — this isolates the replay machinery from plug-in estimation error. An engine re-deriving the replay independently (bootstrap: multinomial weights vs `boot::boot`) is the strong check; one sharing the replay code only validates wiring.
- 2026-07-17 (M30): a design spec leaning on a dependency's parameters must verify each against the *claimed floor version's* source, not the installed one — the coord spec tabled `thetalim`/`rlim`/`reverse`/numeric `r.axis.inside` (all ggplot2 4.0.0-only) under a claimed 3.5.0 floor because it was drafted against 4.0.3. Pin capability claims to the version you *claim*, not the one you *have* (generalizes D-014).
- 2026-07-18 (M31, M32): subclass `CoordRadial` by copying a stock `coord_radial(...)`'s computed fields (`limits`/`theta`/`r`/`arc`/`expand`/`reverse`/`r_axis_inside`/`rotate_angle`/`inner_radius`/`clip`) into `ggproto(NULL, CoordCircumplex, ...)`; the stock transform already carries the circumplex conventions — verify by transforming known points, don't reimplement. CRITICAL: pin the angular range COORD-SIDE (`thetalim=c(0,360)`, `expand=FALSE`), NEVER via `scale_x_continuous(limits=)`, which censors a seam-straddling arc's unwrapped `xmax>360` to NA; an empty `ggcircumplex()` needs `geom_blank()` over `[0,360]×[0,amax]` to train scales. - 2026-07-18 (M31): in a bare `Rscript`/`test_dir` env vdiffr auto-SKIPS the comparison (svglite/font mismatch), so plot changes look "green" while stale baselines go unchecked; to regenerate, delete the stale `_snaps/<file>/*.svg` and re-run under `NOT_CRAN=true`. - 2026-07-18 (M31): after a coord rewrite the canvas furniture is the coord's panel grid, not drawn geom layers — plot-structure tests must locate layers by geom class (`inherits(l$geom, "GeomSsmArc")`), never a hardcoded `data[[6]]` index, and spoke labels come from the x-scale (`ggplot_build(p)$layout$panel_scales_x[[1]]$get_labels()`), not a `geom_label` layer. A passing vdiffr baseline is NOT a fencing test for a behavioral criterion — assert the property at grob level (`ggplotGrob` → panel-grid `gp$col`).
- 2026-07-18 (M32, M35): `is.na()` does NOT reject `±Inf`, so an infinite numeric API arg slips past an `is.na()` guard and errors cryptically deep in render (`Inf %% 360` → `NaN`, never naming the arg). Guard user-facing numeric args with `!is.finite()`. Recurs a layer down: `ssm_has_location()` is `!is.na()`-based, so `±Inf` reads as a LOCATED point and NaNs a `cumsum()` unwrap — any new caller feeding it user-supplied numbers must `!is.finite()`-guard first.
- 2026-07-17/18 (M27, M33): **unwrapping `ssm_draws()` displacement intervals.** Non-contrast rows wrap each CI endpoint independently into [0, 360) (only the *contrast* row is realigned onto the estimate's branch, `R/ssm_bootstrap.R` `if (contrast)`), so a seam-straddling interval has `d_lci > d_uci`. Where the estimate is within a half-turn of BOTH bounds (contrast rows, coverage checks) shift each endpoint by its signed circular distance, `((bound - est + 180) %% 360) - 180` — never by the estimate's branch offset, which inverts the ribbon. But that clamps bounds into (-180, 180] of the estimate, so it cannot represent a stored interval whose CCW arc exceeds 180°: a 337° "displacement unknown" interval renders as a 23° INVERTED band. For arbitrary non-contrast intervals anchor the lower bound — `lo <- branch - ((est - lci) %% 360); hi <- lo + ssm_arc_span(lci, uci)`. `check()` catches neither; the figure just renders wrong.

- 2026-07-18 (M34): agent-written file content can carry leaked tool-call scaffolding — a `Write` of a vignette shipped literal `</content>`/`</invoke>` lines at the tail, and `devtools::check()`, `check_pkgdown()`, AND a 9-job CI matrix all passed, because pandoc emits unmatched closing tags as raw HTML and browsers drop them. - 2026-07-18 (M34): `ssm_analyze_long()` derives occasion order from the column TYPE — first-appearance `unique()` for character, `levels(droplevels())` for a factor — and `factor()` sorts levels alphabetically, so a default-factor `wave` yields `T1, T10, T2`. The roxygen hedges this correctly; prose flattening it into "occasions appear in the order they were supplied" is FALSE. - 2026-07-18 (M36): a legend key whose break exists but whose GLYPH is missing is a `show.legend` problem, not a data-presence problem — under the default (`NA`) a layer claims only the breaks its own data contains, so `scale_*_manual(limits=, drop = FALSE)` keeps the label while the symbol slot renders as a `zeroGrob`. `show.legend = TRUE` on the existing layer is the whole fix; `override.aes` does not reach a keyless break, and presence layers (zero-row, `alpha = 0`) work but are inert machinery inviting deletion. Test by reading key grobs: each key is a gTree holding a `legend.key.rect` plus a `points` grob or a `zeroGrob`; count EVERY `points` grob per key (not the first) to catch two layers overdrawing one key.
- 2026-07-18 (M36): "it works" is not "it is the mechanism" — a shipped fix carried a comment explaining a zero-row presence layer that contributed nothing (removing it left the vdiffr baselines BYTE-IDENTICAL), and plan and implementation inherited the false premise from the same probe. - 2026-07-18 (M37): a CUSTOM optional aesthetic mapped to a discrete column silently destroys a layer — `add_group()` builds `group` from EVERY discrete column when the caller maps none (only `label`/`PANEL` exempt, no extension point), so a character `order` aes put each row in its own group and `GeomPath` returned a `zeroGrob`: nothing drawn, no error, and alphabetical `T1`/`T10`/`T2` misordering — exactly what the aesthetic existed to prevent. Every test used a NUMERIC order column, where it works. Prefer `geom_path()` parity (data row order + `group`); ordering belongs in the wrapper that knows the true order. Render-and-inspect again (M33): an arrow terminating AT a point marker is drawn UNDER it and invisible — draw an arrowed path last, head sized to clear the marker.
- 2026-07-18 (M38): patching a `ViewScale`'s `breaks` after the parent coord builds it desynchronizes it from anything the *scale* pairs positionally with its own breaks — a scale carrying explicit `labels` aborts the build on the length mismatch, and blanking an appended entry by index into `NULL` labels fabricates literal `NA` labels. Ask the scale to label only its own breaks and add the appended entry separately. Neither path is reachable through the package's own API, so the suite and a 15-figure vignette sweep passed over both.
- 2026-07-18 (M38): calibrating a label-collision rule from break spacing calibrates the wrong quantity — collisions track rendered label *width*, so an arithmetic estimate of the safe threshold was off by half and only rendering the candidate outcomes at each ratio exposed it (`1.00`/`1.10` printing as `1.0010`). Render the candidates before writing the rule.
- 2026-07-19 (M7): **a step that doesn't run reports success** — twice. `check(args = "--no-manual")` skips PDF-manual generation, so literal Greek in roxygen cleared two local 0/0/0 checks and failed CRAN-blocking on win-builder; the regression guard added for it then keyed off `test_path("..","..","man")`, absent under `R CMD check` (installed packages carry `help/`), so it skipped in CI, in `check()`, and on CRAN — live only under a bare `devtools::test()`. Grep the log for the step's own OK line (`checking PDF version of manual ... OK`); never read `Status: OK` as coverage. Source Rd via `tools::Rd_db()` so a guard survives installation, and deny-by-default on hostile characters — the enumerated class leaked arrows, primes, and letterlike symbols. **M57 sharpened this: `devtools::check()` itself defaults to `manual = FALSE`, so the PDF-manual step is skipped even by the bare `devtools::check()` the `r-package` profile's consistency-gate calls the "full check" — no `--no-manual` argument required to lose it. Grep the log for `checking PDF version of manual`; if that line is absent the step did not run, and build the manual directly (`R CMD Rd2pdf --no-preview --force`) when a milestone touches roxygen.**
- 2026-07-19 (M39): a "sibling of the label grob" is NOT co-placed with it — ggplot2's radial-axis labels carry a per-label `rot`, and `rectGrob` has none, so a plate sharing the label's x/y renders axis-aligned and slides off. The structural fence passed the broken version; only rendering caught it — the third "green because it never looked" (after M31 vdiffr auto-skip, M7 --no-manual).
- 2026-07-19 (M39): `stringWidth()`/`stringHeight()` take a character vector, so `as.character()` on a plotmath label measures its deparsed source (`"gamma^2"`) not the rendered glyph — a plate several times too wide. - 2026-07-19 (M40, extended M42/M45/M47): **an `Extraction:` status may claim only what each channel actually saw.** A human attestation of an OLD record does not transfer to a NEW page built from it — authoring a source note is itself a fresh extraction — so M40 claimed "verified twice and independently" while eight Appendix-A values rested on `pdftotext` alone. The gitignored shelf is LIVE, so re-check absence claims at merge, not at write. **M45: it recurs for page RANGES** — a status naming rendered pp. X–Y overclaims any anchor outside it (hubert "pp.176–177" missed p.175's exact p-value; tracey "p.165" missed p.166's `p=.0167`), and re-rendering the missing page caught a printed slip (Tracey ".0167 (1/720)"; =1/60) the diff/blame lenses missed for lack of the image — verify value coverage, not headline coverage. - 2026-07-19 (M41): a source note's "nothing in the repo uses this" claim must be grepped for the source's FORMULAS, not its citation — M41 wrote that nothing computes Browne & Cudeck's RMSEA equations while `R/cpm_fit.R:1049,1011-1028` had implemented eqs. 13/14 all along, UNATTRIBUTED, so the citation grep saw nothing and the page shipped a falsehood plus an incomplete `Traces to`. - 2026-07-25 (M58): **a package removed from a CI dependency allowlist is never EVICTED from the Actions cache.** `setup-r-dependencies` restores the whole library, installs the new lockfile INTO it, and re-saves the lot, so the package stops being REQUESTED while still being RESTORED — brms sat in every Ubuntu cache for four days after M52 dropped it, and M52's 60s->41s was a resolution effect, not the Stan stack leaving. A "we no longer install X" claim only becomes true after a cache purge, and the purge must delete every key sharing the `restore-keys` PREFIX, not just the one job's key (a narrow delete just falls back to a neighbour's cache). Verify by grepping the job's session-info for X, never its lockfile — and note the two answer different questions.
- 2026-07-25 (M58): `paths-ignore` on a `pull_request` trigger is evaluated against the WHOLE PR diff, not the pushed commit, so a tracking-only commit mid-PR still runs every workflow; only `push` filters read that push's own files. - 2026-07-26 (M59): **a numeric tolerance calibrated on one machine is not a tolerance.** An oracle pinning lavaan's (N−1)/N convention passed at ~3e-11 relative on macOS and failed CI at 1.3e-8 — and only in the `covr` job: instrumentation perturbs optimizer results where the plain check job on the SAME OS passes, so a green `R CMD check` is not evidence `test-coverage` will pass. Set the bar from the DISCRIMINATION required (here the alternative hypothesis is off by relative 1/n, so 1e-6 still fences at 20×) with orders of magnitude left for platform noise — never from the value one machine prints. Same family as M20's pole-float ulp lesson, which this milestone's own plan cited before walking into it. **M61 adds the direction trap: `expect_equal(x, truth, tolerance = t)` in testthat 3e is RELATIVE, so `tolerance = .05` against a truth of `.08` is a `.004` window — two component assertions failed at `.058` vs `.08`, an ordinary finite-sample draw, until rewritten as explicit `expect_lt(abs(est - truth), .05)`. State an absolute bound absolutely.** **M64 generalizes the family beyond code: both of its gated amendments came from writing a FENCE before the thing it fences existed.** (i) The same one-run trap, twice, in prose records rather than tests — an acceptance criterion pinned one-vs-two-stage agreement at 5e-4 off a four-decimal printout (the committed script measures 6.2e-4, so the criterion would have failed its own review), and a review brief quoted `|mean| <= 6e-17` for `scale()` off a scratchpad seed (the script measures 7.9e-17). A record is not exempt because no test asserts it: a reviewer re-runs the script and the number does not match. Derive the bound from the DISCRIMINATION required and state it comparatively — M64's replacement, "under 5% of the estimate's own SE", keeps 20x headroom to the one-SE disagreement it rules out and survives a reseed. (ii) **A criterion fencing the CONTENT of an RB/RR artifact must be satisfiable before that artifact is archived**, since `reviews/archive/` is history under IP4: AC2 required the brief to state all three fixed design positions, the brief stated two, and no legal edit could make it comply — fence the decision RECORD instead, or write the criterion after the brief exists. The corollary is why that miss was harmless: leaving one question unanchored was the better brief, because the reviewer then chose one-stage FIML unprompted, which is independent evidence rather than an echo.
- 2026-07-26 (M60): **replacing a narrow validity check with a general one silently drops whatever the narrow one refused by ACCIDENT.** The octant-only `identical(sort(angles %% 360), sort(octants() %% 360))` refused a non-finite angle for a reason nobody wrote down: `Inf %% 360` is `NaN`, `sort()` drops it, and the resulting LENGTH MISMATCH failed the comparison. The general equal-spacing predicate computes `k` from the surviving angles, so the same input read as equally spaced and died in `qr.solve()` naming nothing (caught in review, not by the 589-assertion suite). When generalizing a gate, enumerate what the old one rejected INCIDENTALLY — side effects of its data structure, not its stated intent — and re-assert each. `anyNA()` never rejects `±Inf`: the M32/M35 lesson, third recurrence.
- 2026-07-26 (M60): **a mutation that perturbs a quantity the model is provably invariant to CANNOT redden, and reading that null as missing coverage is the error.** Rotating every fixed weight in the axes-reliability syntax by 0.5 degrees left all tests green — correctly, because Σ depends only on `cos(θi − θj)`, which is what "no preferred rotation" means. Perturbing ONE scale's angle reddened 19 tests. Before treating a green mutation as a coverage hole, ask whether the estimator is identified in that direction at all; and when it is not, record the null result so a later session does not re-chase it. Twice more in the same milestone a comment claimed a mechanism the code did not have (a wrap-around gap implied by the interior gaps; a `split()` character-sort hazard that R does not have, since `split()` coerces a numeric group vector with `factor()`, whose levels sort NUMERICALLY) — assert R semantics by running them, not from memory.
