- 2026-07-13 (M19): a caution/guardrail that ships behind a design deferral (M18-D3's placeholder unconditional free caution) often ships UNTESTED — grep for a test of the exact wording before assuming coverage. The free bordered σ-Hessian is far more singular-prone than the diag one (NA SE in ~52–55% of N=250 fits vs ~0 for diag), so free-family small-N analytic CIs are often simply undefined — a distinct failure mode from mis-coverage, worth conditioning oracle stats on (count SE-failures separately, don't drop silently).

- 2026-07-12 (M11): mechanical test-fixture rewrites must be validated with `devtools::check()`, not just `devtools::test()`/`load_all()`. Consolidating inline populations into a `sem_canonical_pop()` helper removed a block's `a`/`cc` locals it still used to rebuild `lambda1`; `test()`/`test_file()` under `load_all()` **masked** the `object 'a' not found` (an earlier block's `a` leaked into scope), and only the clean-env R CMD `check()` caught it. - 2026-07-12 (M10): `cairn_validate.py`'s ISO-date check flags any `\d+/\d+/\d+` token as a malformed date — writing a `check()` result as "0/0/0" in a tracking file trips it. Write "0 errors / 0 warnings / 0 notes" (spaces around slashes) instead. Also: when a milestone Goal names a function family but the enumerated Scope/Tasks list specific sites, grep the whole family first — the plan's site list drifts (post-merge line shifts) and can silently omit members (M10 missed `ssm_analyze()`'s own validators; the two-lens review caught it).
- 2026-07-12 (M13): a regression-guard test that **re-types** the production expression instead of calling the production code path has NO teeth — the review (F1) caught a "CPM angle-CI oracle" whose end-to-end fixture never straddled the pole, so a linearized `cpm_fit.R:1119` passed it. Prove a guard bites by breaking the guarded line (`assignInNamespace` a linearized `quantile.circumplex_radian`) and confirming red. To force a deterministic 0/360 straddle through `cpm_fit()`: put a *non-reference* item exactly on the pole, sample raw data via `cpm_implied_cor()`+`chol()`+`rnorm()` (seeded, base-R, no MASS), and assert the reported CI **wraps** (`Angle_lci > Angle_uci`) — a linear quantile yields a ~357° non-wrapped span instead. Such a bootstrap+optimization test is deterministic given the seed and (large-margin wrap) robust enough to run in CI under `skip_on_cran()` alone; Windows CI green confirmed no BLAS flip.
- 2026-07-12 (M16): running the suite from bare `Rscript` silently SKIPS `skip_on_cran()` tests (NOT_CRAN unset) — set `NOT_CRAN=true` to exercise them; `testthat::test_dir/test_file` default `stop_on_failure=TRUE` (throws "Test failures" and aborts your aggregation — pass `stop_on_failure=FALSE`); and the results data.frame's `failed` column EXCLUDES `error` — a test that errors shows `failed=0`, so always sum `error` too. Also: `aw2009` is too small for `ssm_ci_accuracy()` (pooled n < #scales → "Too few observations" error); use a `jz2017` fit for any diagnostic-based test.
- 2026-07-12 (M16): a name collision with a loop variable can corrupt a display-only surface while leaving the computation correct — a constant `cert_k <- 0.35` added atop `ssm_ci_accuracy()` was clobbered by the loop's existing `cert_k <- rowSums(...)` (certified count), so the summary echo printed garbage while the actual certification (a separate `ssm_certified()` call) stayed right; behavioral tests all passed and only a snapshot caught it. Grep the function for the name before introducing a constant, and snapshot the echo surfaces, not just the computed numbers. When rewriting live-rendered vignette prose after a rule change, RE-RUN the exact vignette config and rewrite from the actual new output — the narrative claims (which profile is certified, whether a caution fires) flip with the rule and cannot be edited by guesswork.
- 2026-07-13 (M18): when a milestone changes the *semantics* of a function's return value (not just its diff), the bug lives in the CONSUMERS, not the diff — `cpm_fit()`'s `matrices$Phat` went correlation→covariance under `scaling="free"`, and `ssm_ci_accuracy(cpm=)` silently embedded the non-unit diagonal into a correlation population. The diff-bug (Opus) reviewer cleared the consumer by checking only its internal unit-fit path; the blame-history lens caught the reachable user-supplied `cpm=` path it missed. Lesson: on any return-value-semantics change, grep every consumer of that field and guard the ones that assumed the old invariant; the multi-lens fan-out earns its cost exactly here (one lens's blind spot is another's catch). Guard, don't silently coerce — refuse the unsupported combination with a clear message + regression test.
- 2026-07-16 (M21): a standalone `rmarkdown::render()` of a vignette runs against the *installed* package, not the dev tree — a dev-line vignette (here: `fit_structure()`, absent from installed 1.2.0.9999) fails spuriously and the failure points at an innocent chunk far from your edit. `devtools::check()` is the authoritative vignette build (it installs the source package into a temp lib first); don't chase standalone-render failures before comparing `packageVersion()` against DESCRIPTION.
- 2026-07-16 (M20): the 0/360 pole's float label is platform- and path-dependent — R-level `%%` clamps the fmod edge to exact 0 (macOS) while the C++ `modu` estimate path yields exact 2π, and cross-platform last-ulp libm variation can leave a pole residue a few ulp wide; so any pole-snap window must be ≥ a few ulp of 2π (M20: 16*eps ≈ 4 ulp — a 2*eps window is thinner than ONE ulp of 2π and only ever catches bit-exact 2π), and estimate-path boundary assertions follow G2's either-label rule — reserve `expect_identical(…, 360)` for value-level-snapped endpoint contracts, never for values that ride through libm trig.
- 2026-07-16 (M22): a warm start added to a multi-start battery must be EXCLUDED from the reproduced/acceptance count — counting it as an independent group silently liberalizes acceptance (at correlation input the unit-solution seed starts ≈ at the free optimum, so it "reproduces" anything). The failure was invisible to every targeted test and surfaced only in the full suite's stochastic SE cross-check oracle (3 permutation-basin replicates, each with exactly 1 native group at min F) — full-suite runs after estimation changes earn their minutes. Pin such semantics with a tiny extracted helper (`cpm_reproduced()`) unit-tested deterministically, NOT by asserting a real fit's accepted flag (basin outcomes ride knife-edge optimizer/BLAS luck across platforms).
- 2026-07-16 (M22, tracking): before re-adding a decision's spun-off candidate as an "orphan fix", grep milestones/archive/ AND git log for the source ID (here RR01) — terminal-row retention prunes done rows from the ROADMAP, so a missing row never proves the work wasn't done (M13 had shipped all four RR01 follow-ups; the morning cleanup re-added them as a candidate).

- 2026-07-16 (M23): a spec's quantitative claims need the adversarial-derivation treatment code gets — the draft's "paired CIs are narrower at ρ>0" was false for Δa/Δd (delta-method cross term ∝ ρ·cos Δd; reverses past |Δd|=90°) and survived drafting; only independent derivation (RR06) caught it. - 2026-07-16 (M24): a dependency-cost claim ("adopting X raises the R floor to 4.1") must be benchmarked against the EXISTING Imports' effective floor computed by the same method, not the declared DESCRIPTION floor — ggplot2/htmlTable already imposed 4.1, so the new closure's floors were neutral; the diff-bug lens refuted the draft's floor-jump claim with the memo's own `package_dependencies()` recipe. - 2026-07-16 (M25): an "independence baseline" for a MEAN-BASED estimator cannot be built by permuting rows within the drawn sample — group means are permutation-invariant, so the estimates keep the paired sampling distribution while the engines see independent data (overcoverage on one side of the reversal, undercoverage on the other, efficiency ratios ≈ 1). Draw the comparison arm from FRESH units instead; a reversal-expecting oracle cell (M23 lesson) is what exposed it.
- 2026-07-16 (M25): never resolve numeric column indices to names before subsetting a data.frame — `[.data.frame` resolves duplicated names to the FIRST match, so cbind-ed same-named blocks silently collapse onto block 1 (a wrong-answer channel, not an error); subset by position, and guard cross-block selections with an overlapping-columns error. Same family: positional info-column drops (`-c(1:3)`) break when a conditional column appears — drop by name.
- 2026-07-12 (M15): a "display consistency" change to a diagnostic has more surfaces than the obvious print method — for `ssm_ci_accuracy()` the certification-conditional contrast figure lived on FOUR surfaces (`coverage$Coverage_conditional`, the `verdict` Class, `guardrail$Cert_rate`, AND `plot.circumplex_ci_accuracy()`'s "Displacement (certified)" panel). Key design split that generalises: *measured quantities stay in the returned object; only interpretive/presentation surfaces (verdict/print/summary/plot) follow the print method's stance* — so relabel the verdict `Parameter` (`"d_conditional"`→`"d"`) rather than silently changing its contents (a greppable, self-describing change beats a silent value swap under an unchanged label). Existing snapshot/plot fixtures were profile-only, so contrast behaviour had NO guard until this milestone added a contrast print snapshot + a data-level (`plot(res)$data`) panel-exclusion test — check fixture coverage of the branch you're changing, don't assume the snapshot covers it.
- 2026-07-16 (M26): R's `%%` is not the C++ kernel's `modu()` at the pole — R applies a second reduction sending a tiny-negative angle to 0 where `modu()` gives 2π; for kernel bit-parity wrap atan2 output with `d + 2*pi*(d < 0)`, never `%%`.
- 2026-07-16 (M26): bit-exact oracle comparisons must compare values produced by the same single conversion expression — converting one side degrees→radians adds a rounding step and fails `expect_identical` by 1 ulp.
- 2026-07-17 (M27): `ssm_draws()` non-contrast displacement intervals report each CI endpoint independently wrapped into [0, 360) (only the *contrast* row is realigned onto the estimate's branch, `R/ssm_bootstrap.R` `if (contrast)`), so a seam-straddling interval has `d_lci > d_uci`. When plotting or unwrapping a trajectory of such intervals, shift each endpoint by its *signed circular distance* from the estimate — `((bound - d_est + 180) %% 360) - 180` added to the unwrapped estimate — NOT by the estimate's branch offset (which throws a straddling bound a full turn off and inverts the ribbon). `devtools::check()` can't catch this: the chunk runs without error, the figure just renders wrong — the diff-bug lens (score 97) caught it. The oracle's own `d_covered()` already did it right; reuse that branch-relative pattern.
- 2026-07-17 (M27): a certification-firing oracle danger cell must put its degraded truth *genuinely* at the origin (a→0), not merely low — the first run placed a(2)=0.02 (≈0.9 SE of signal), inside the D-007 rule's power-onset region, so the cert-gate missed (.058 > .05) while every other gate passed; moving the truth to 0.01 (the named a→0 regime) fixed it with gates unchanged. Calibrate a "the guardrail must fire" cell to the regime the guardrail names, and record the miss + the move rather than quietly retuning.
- 2026-07-17 (M28): collapsing a per-row long column to one value per person by the first *physical* row (`col[match(ids, id)]`) silently discards a validated value when that row is NA — a covariate recorded only at a later wave becomes NA and the person is then dropped by `ssm_analyze()`'s NA-grouping deletion. Take the first *non-NA* value per person (`split(seq_len(nrow), id_index)` → first non-NA row), indexing the original column so factor/character/numeric type is preserved. NA-tolerant validation + first-row extraction is an order-dependent silent-drop trap: two independent review lenses (diff-bug + blame-history, scored 96) caught it but the round-trip-equivalence test did not — its fixture had no NA-grouping cell. When a reshape wrapper collapses repeated per-person metadata, pair the equivalence oracle with a "blank the first-occasion value, assert results unchanged" regression.
- 2026-07-17 (M29): a loose statistical assertion in a NEW diagnostic test can pass in isolation yet flake only in the full suite — the object-building `ssm_analyze()` (bootstrap) inherits leaked cross-file RNG state, and for `ssm_ci_accuracy()` that state feeds the near-zero/margin-rung detection (via the object's stored `a_lci`/`a_uci`), shifting the simulated ladder conditions. Seed EVERY stochastic call in the test, including the `ssm_analyze()` that builds the object, not just the `ssm_ci_accuracy()` call; prove determinism by running the file under varied incoming RNG (`set.seed(x); runif(n)` before `test_file`), not just standalone.
- 2026-07-17 (M29): to validate a plug-in coverage diagnostic, compare its REPORTED coverage to a direct Monte-Carlo of the REAL shipped procedure at the SAME plug-in (draw from the object's own μ̂/Σ̂, run `ssm_analyze()` per replicate, tally coverage of the object's own point estimates as the fixed truth) — this isolates the replay machinery from plug-in estimation error (the diagnostic's inherent limitation). The engine that re-derives the replay independently (bootstrap: multinomial weights vs `boot::boot`) is the strong check; an engine that shares the replay code (MC: both call `ssm_mc_replicates`) only validates wiring.
- 2026-07-17 (M30): a design spec leaning on a dependency's parameters must verify each against the *claimed floor version's* signature/source, not the installed version — the coord spec tabled `thetalim`/`rlim`/`reverse`/numeric `r.axis.inside` (all ggplot2 4.0.0-only) under a claimed 3.5.0 floor because it was drafted against the installed 4.0.3; Fable caught it against the v3.5.2 source. - 2026-07-18 (M31): subclass ggplot2 `CoordRadial` by building a stock `coord_radial(...)` and copying its computed fields (`limits`/`theta`/`r`/`arc`/`expand`/`reverse`/`r_axis_inside`/`rotate_angle`/`inner_radius`/`clip`) into `ggproto(NULL, CoordCircumplex, ...)` — robust to ggplot2's internal setup changing across versions. The stock transform ALREADY carries the circumplex conventions: `start=pi/2`+`reverse="theta"` gives LM=360 CCW-from-right, `d∈{0,360}` map to one point, and a rect `xmax>360` wraps periodically the short way — verify by transforming known points, don't reimplement. CRITICAL: pin the angular range COORD-SIDE (`thetalim=c(0,360)`, `expand=FALSE`), NEVER via `scale_x_continuous(limits=)`, which censors a seam-straddling arc's extension-unwrapped `xmax>360` to NA and silently breaks the wedge. - 2026-07-18 (M31): regenerating vdiffr baselines after an intended render change — in a bare `Rscript`/`test_dir` env vdiffr auto-SKIPS the comparison (svglite/font mismatch), so plot changes look "green" while stale baselines go unchecked; delete the stale `_snaps/<file>/*.svg` and re-run (missing baselines are recreated), and run under `NOT_CRAN=true` to actually compare. - 2026-07-18 (M31): after a coord rewrite the canvas furniture is the coord's panel grid, not drawn geom layers — plot-structure tests must locate layers by geom class (`inherits(l$geom, "GeomSsmArc")`), never a hardcoded `data[[6]]`/`[[7]]` index, and spoke labels come from the x-scale (`ggplot_build(p)$layout$panel_scales_x[[1]]$get_labels()`), not a `geom_label` layer. - 2026-07-18 (M32): to move a `CoordRadial` subclass's radial (amplitude) axis, set `self$r_axis_inside` (numeric = theta angle in DATA/degree units) inside `setup_panel_params` BEFORE delegating to the parent (same mutate-self pattern as `self$limits$r`), computing the angle from `scale_x$get_breaks()` (the spokes). The parent feeds `r_axis_inside` only to `axis_rotation` (guide placement), never xlimits/pole/seam — so dynamic placement is orthogonal to the pinned thetalim/pole/seam invariants (verify by transforming known points; can't fence label overlap at grob level — the label grobs are nested unnamed gTrees, so fence the off-spoke placement property instead). Export ggproto generators under a shared `@name <pkg>-ggproto` page with `@keywords internal` + `@format/@usage NULL`: `check_pkgdown()` passes without a `_pkgdown.yml` row (internal topics are exempt), but a user-facing export like `theme_circumplex()` still needs its row.
- 2026-07-18 (M32): `is.na()` does NOT reject `±Inf` (`is.na(Inf)` is FALSE), so an infinite numeric API arg (an angle, a limit) slips past an `is.na()` guard and only errors cryptically deep in render (`Inf %% 360` → `NaN`, never naming the arg); guard user-facing numeric args with `!is.finite()` (catches NA/NaN/±Inf). The diff-bug review lens caught it on the new `r_axis_angle`; the sibling `amax`/`center` guards carry the same pre-existing gap.
- 2026-07-18 (M33): the M27 per-bound unwrap `((bound - est + 180) %% 360) - 180` is correct ONLY where the estimate sits within a half-turn of both bounds (contrast rows, coverage checks — its original home). It clamps every bound into (-180, 180] of its estimate, so it silently CANNOT represent a stored displacement interval whose CCW arc exceeds 180° — a near-zero-amplitude occasion's 337° "displacement unknown" interval rendered as a 23° INVERTED band with the estimate outside its own bounds, reading as the most precise point in the series (no warning; `check()` green). For arbitrary non-contrast intervals anchor the lower bound and derive the upper from the stored span: `lo <- branch - ((est - lci) %% 360); hi <- lo + ssm_arc_span(lci, uci)`. Generalizes the M27 lesson rather than replacing it; agrees to the digit on narrow, seam-straddling, and wide-but-centred intervals.
- 2026-07-18 (M33): an assertion can be guaranteed by the very defect it is meant to catch — `expect_true(all(uci - lci < 180))` is arithmetically implied by the (-180, 180] clamping above, so it passed while the ribbon was inverted. When guarding an angular interval, assert the width EQUALS `ssm_arc_span(lci, uci)` (the invariant at every width), never that it falls under a bound the implementation already enforces. Same family as the M13 teeth rule, one level subtler: the fixture straddled the seam, but no fixture reached the wide-arc regime, so the mutation test only ever proved teeth against a linear/naive-offset mutation.
- 2026-07-18 (M33): `results$Occasion` is a CHARACTER column and `details$occasions` is the only ordering authority — a discrete ggplot2 scale re-sorts it alphabetically, flipping a `T10`/`T2` pair and silently reversing the time axis. Factor against `details$occasions` in any occasions plot. Also: the prior-PR-comments review lens is a permanent clean no-op in this repo (every merged PR has 0 review comments; review happens through cairn, recorded in `LESSONS.md` and `milestones/archive/`), so its "no findings" carries no evidential weight here.
- 2026-07-18 (M33): rendering a new plot and LOOKING at it catches what no data-level test does — an ungrouped series drawn in a ggplot2 hue that encodes nothing, and a `scale_shape_manual` legend key rendered invisible because it inherited a pale group colour (fix: `guides(shape = guide_legend(override.aes = list(color = "black")))`). Budget one render-and-inspect pass per new figure; the data-level fences and the vdiffr baseline both pass a figure that reads wrong.
- 2026-07-18 (M35): a wide-arc angular fixture CENTRED on its estimate does not discriminate — the (-180, 180] clamping expression reproduces the correct width there by symmetry, so a centred fixture passes against the very bug it targets. Place the estimate deliberately OFF-CENTRE in the arc (M35: est 300 in the CCW arc 190→170, 110° above the lower bound and 230° below the upper); real diffuse near-origin draws are asymmetric anyway, since the circular median need not sit midway between the quantiles. One level subtler than the M33 teeth lesson it extends: there the fixture never reached the wide-arc regime; here it reached it but at the one point in it where the bug is invisible.
- 2026-07-18 (M35): to extract a shared helper out of a prior milestone's code and still use that milestone's suite as an UNTOUCHED fence, parameterize the helper by the varying column's *name* rather than renaming the column to a neutral one — the old path keeps its own column (`Occasion`), the new path carries the caller's (`wave`), zero test edits, and the fence claim stays literal instead of "green after I updated the assertions". Also: `ssm_has_location()` is `!is.na()`-based, so `±Inf` reads as a LOCATED point (`is.na(Inf)` is FALSE) and NaNs the rest of a `cumsum()` unwrap — any new caller feeding it user-supplied numbers must `!is.finite()`-guard them first (the M32 lesson, recurring one layer down).
