remembering next time — captured at milestone end, surfaced at plan time.
Not status, not decisions.

- 2026-07-12/18/19 (M13, M33, M35, M40, M43): **a guard has teeth only if you break the guarded line and see it fail.** Five silent failures: (a) the test re-types the production expression instead of calling the code path (M13 — fixture never straddled the pole; force a wrap with an item exactly on the pole, assert `Angle_lci > Angle_uci`); (b) the assertion is arithmetically implied by the defect (M33 — `expect_true(all(uci - lci < 180))` is guaranteed by the clamping it should catch; assert width EQUALS `ssm_arc_span(lci, uci)`); (c) the fixture hits the regime where the bug is invisible (M35 — a wide arc CENTRED on its estimate reproduces the right width by symmetry; place the estimate off-centre); (d) the guard never matched at all (M40 — `cairn_validate`'s INDEX parser reads the first `.md` token after the bullet, so bare-citekey link TEXT is silently not a catalog entry; use the filename); (e) the PROBE was narrower than what it probed (M43 — `pdftotext -layout` splits a display equation across lines, `(N)` marker alone, so a grep pinned to the marker line reads as "equation missing"; that false claim reached a provenance block before review re-ran the command). Prove by mutation, never by eye; never infer coverage from a probe that cannot see what it checks.
- 2026-07-12 (M16): bare `Rscript` silently SKIPS `skip_on_cran()` tests (NOT_CRAN unset) — set `NOT_CRAN=true`; `testthat::test_dir/test_file` default `stop_on_failure=TRUE` (aborts your aggregation — pass `FALSE`); the results data.frame's `failed` column EXCLUDES `error`, so always sum `error` too. Also `aw2009` is too small for `ssm_ci_accuracy()` (pooled n < #scales) — use a `jz2017` fit for diagnostic tests.
- 2026-07-13 (M18): when a milestone changes a return value's *semantics*, the bug lives in the CONSUMERS, not the diff — `cpm_fit()`'s `matrices$Phat` went correlation→covariance under `scaling="free"` and `ssm_ci_accuracy(cpm=)` silently embedded the non-unit diagonal into a correlation population. Grep every consumer of a changed field and guard the ones assuming the old invariant — refuse the unsupported combination with a clear message + regression test, never silently coerce.
- 2026-07-16/18 (M21, M34): **anything run outside `devtools::load_all()` reads the INSTALLED package, not the dev tree.** A standalone `rmarkdown::render()` of a dev-line vignette fails spuriously at an innocent chunk (`devtools::check()` is the authoritative vignette build); a bare `Rscript -e 'library(circumplex); getNamespaceExports(...)'` audited 29 exports instead of the dev tree's 43. Run introspection under `load_all()` and print `packageVersion()` to prove which tree answered.
- 2026-07-16 (M20): the 0/360 pole's float label is platform- and path-dependent — R's `%%` clamps the fmod edge to exact 0 (macOS) while the C++ `modu` path yields exact 2π, and last-ulp libm variation leaves a pole residue a few ulp wide. Any pole-snap window must be ≥ a few ulp of 2π (M20: `16*eps` ≈ 4 ulp; a `2*eps` window is thinner than ONE ulp of 2π and catches only bit-exact 2π), and estimate-path boundary assertions follow G2's either-label rule — reserve `expect_identical(…, 360)` for value-level-snapped endpoint contracts, never values riding through libm trig.
- 2026-07-16 (M22): a warm start added to a multi-start battery must be EXCLUDED from the reproduced/acceptance count — at correlation input the unit-solution seed starts ≈ at the free optimum, so counting it as an independent group silently liberalizes acceptance. Invisible to every targeted test; surfaced only in the full suite's stochastic SE cross-check oracle — full-suite runs after estimation changes earn their minutes. Pin such semantics with a tiny extracted helper (`cpm_reproduced()`) unit-tested deterministically, NOT by asserting a real fit's accepted flag (basin outcomes ride BLAS luck).
- 2026-07-16 (M23): a spec's quantitative claims need the adversarial-derivation treatment code gets — "paired CIs are narrower at ρ>0" was false for Δa/Δd (delta-method cross term ∝ ρ·cos Δd; reverses past |Δd|=90°) and survived drafting; only independent derivation (RR06) caught it. Write efficiency/coverage claims as conditionals with the condition derived, and give the oracle a cell that EXPECTS the reversal.
- 2026-07-16 (M24): a dependency-cost claim ("adopting X raises the R floor to 4.1") must be benchmarked against the existing Imports' *effective* floor computed the same way, not the declared DESCRIPTION floor — ggplot2/htmlTable already imposed 4.1, so the new floors were neutral. Run any "delta" analysis on the baseline too, or the delta is against a fiction.
- 2026-07-16 (M25): an "independence baseline" for a MEAN-BASED estimator cannot be built by permuting rows within the drawn sample — group means are permutation-invariant, so estimates keep the paired sampling distribution while the engines see independent data. Draw the comparison arm from FRESH units; a reversal-expecting oracle cell (M23) is what exposed it.
- 2026-07-16 (M25): never resolve numeric column indices to names before subsetting a data.frame — `[.data.frame` resolves duplicated names to the FIRST match, so cbind-ed same-named blocks silently collapse onto block 1 (a wrong-answer channel, not an error). Subset by position and guard cross-block selections with an overlapping-columns error. Same family: positional info-column drops (`-c(1:3)`) break when a conditional column appears — drop by name.
- 2026-07-16 (M26): kernel bit-parity has two traps. R's `%%` is not C++ `modu()` at the pole — R applies a second reduction sending a tiny-negative angle to 0 where `modu()` gives 2π; wrap atan2 output with `d + 2*pi*(d < 0)`, never `%%`. And bit-exact oracle comparisons must compare values from the same single conversion expression — converting one side degrees→radians adds a rounding step and fails `expect_identical` by 1 ulp.
- 2026-07-17 (M27): a certification-firing oracle danger cell must put its degraded truth *genuinely* at the origin (a→0), not merely low — a(2)=0.02 (≈0.9 SE of signal) sits inside the D-007 rule's power-onset region, so the cert-gate missed (.058 > .05); moving the truth to 0.01 fixed it with gates unchanged. Calibrate a "the guardrail must fire" cell to the regime the guardrail names, and record the miss + the move rather than quietly retuning.
- 2026-07-17 (M28): collapsing a per-row long column by the first *physical* row (`col[match(ids, id)]`) silently discards a validated value when that row is NA — a covariate recorded only at a later wave becomes NA and the person is dropped by `ssm_analyze()`'s NA-grouping deletion. Take the first *non-NA* value per person (`split(seq_len(nrow), id_index)` → first non-NA row), indexing the original column so type is preserved. The round-trip-equivalence test missed it — its fixture had no NA-grouping cell. Pair any such reshape oracle with a "blank the first-occasion value, assert results unchanged" regression.
- 2026-07-17 (M29): a loose statistical assertion in a NEW diagnostic test can pass in isolation yet flake in the full suite — the object-building `ssm_analyze()` (bootstrap) inherits leaked cross-file RNG state, which for `ssm_ci_accuracy()` feeds near-zero/margin-rung detection via the stored `a_lci`/`a_uci`. Seed EVERY stochastic call including the `ssm_analyze()` that builds the object, and prove determinism under varied incoming RNG (`set.seed(x); runif(n)` before `test_file`), not standalone.
- 2026-07-17 (M29): to validate a plug-in coverage diagnostic, compare its REPORTED coverage to a direct Monte-Carlo of the REAL shipped procedure at the SAME plug-in (draw from the object's own μ̂/Σ̂, run `ssm_analyze()` per replicate, tally coverage of its own point estimates as fixed truth) — this isolates the replay machinery from plug-in estimation error. An engine re-deriving the replay independently (bootstrap: multinomial weights vs `boot::boot`) is the strong check; one sharing the replay code only validates wiring.
- 2026-07-17 (M30): a design spec leaning on a dependency's parameters must verify each against the *claimed floor version's* source, not the installed one — the coord spec tabled `thetalim`/`rlim`/`reverse`/numeric `r.axis.inside` (all ggplot2 4.0.0-only) under a claimed 3.5.0 floor because it was drafted against 4.0.3. Pin capability claims to the version you *claim*, not the one you *have* (generalizes D-014).
- 2026-07-18 (M31, M32): subclass `CoordRadial` by copying a stock `coord_radial(...)`'s computed fields (`limits`/`theta`/`r`/`arc`/`expand`/`reverse`/`r_axis_inside`/`rotate_angle`/`inner_radius`/`clip`) into `ggproto(NULL, CoordCircumplex, ...)`; the stock transform already carries the circumplex conventions — verify by transforming known points, don't reimplement. CRITICAL: pin the angular range COORD-SIDE (`thetalim=c(0,360)`, `expand=FALSE`), NEVER via `scale_x_continuous(limits=)`, which censors a seam-straddling arc's unwrapped `xmax>360` to NA; an empty `ggcircumplex()` needs `geom_blank()` over `[0,360]×[0,amax]` to train scales. To move the radial axis set `self$r_axis_inside` (theta, degrees) in `setup_panel_params` BEFORE delegating to the parent, from `scale_x$get_breaks()`; fence off-spoke placement, not label overlap (nested unnamed gTrees).
- 2026-07-18/19 (M31, M36, M38, M7, M39): **a green result is not coverage — check that the check looked.** Five ways it didn't: (a) the step was skipped by FLAG — `check(args = "--no-manual")` skips PDF-manual generation, so literal Greek in roxygen cleared two local 0/0/0 checks and failed CRAN-blocking on win-builder; (b) the guard was skipped by PATH — the regression test added for (a) keyed off `test_path("..","..","man")`, absent under `R CMD check` (an installed package carries `help/`), so it ran in no gate that ships a release; source Rd via `tools::Rd_db()` so a guard survives installation, and deny-by-default on hostile characters (the enumerated class leaked arrows, primes, letterlike symbols); (c) the comparison AUTO-skipped — in a bare `Rscript`/`test_dir` env vdiffr skips on svglite/font mismatch, so plot changes look green while stale baselines go unchecked; regenerate by deleting `_snaps/<file>/*.svg` and re-running under `NOT_CRAN=true`, where unaffected plots regenerating byte-identically signals only the intended plots moved; (d) the baselines never EXERCISED the change — every M38 canvas baseline used `amax` in {0.5, 0.6, 1.0}, all values the break generator already lands on, so none moved; the fix is to ADD a baseline, not to report the clean run; (e) the probe couldn't ATTRIBUTE — a zero-row presence layer was documented as the mechanism though removing it left the vdiffr baselines BYTE-IDENTICAL, so ablate each moving part separately before writing the comment explaining it. M39 adds a sixth shape: a structural fence passed a visibly broken plate, and only rendering caught it. Grep the log for the step's own OK line (`checking PDF version of manual ... OK`); never read `Status: OK` as coverage.
- 2026-07-19 (M39): a "sibling of the label grob" is NOT co-placed with it — ggplot2's radial-axis labels carry a per-label `rot`, and `rectGrob` has none, so a plate sharing the label's x/y renders axis-aligned and slides off. Give each plate its own `viewport(x, y, angle = rot)` centred on the anchor.
- 2026-07-18 (M31): after a coord rewrite the canvas furniture is the coord's panel grid, not drawn geom layers — plot-structure tests must locate layers by geom class (`inherits(l$geom, "GeomSsmArc")`), never a hardcoded `data[[6]]` index, and spoke labels come from the x-scale (`ggplot_build(p)$layout$panel_scales_x[[1]]$get_labels()`), not a `geom_label` layer. A passing vdiffr baseline is NOT a fencing test for a behavioral criterion — assert the property at grob level (`ggplotGrob` → panel-grid `gp$col`).
- 2026-07-18 (M32, M35): `is.na()` does NOT reject `±Inf`, so an infinite numeric API arg slips past an `is.na()` guard and errors cryptically deep in render (`Inf %% 360` → `NaN`, never naming the arg). Guard user-facing numeric args with `!is.finite()`. Recurs a layer down: `ssm_has_location()` is `!is.na()`-based, so `±Inf` reads as a LOCATED point and NaNs a `cumsum()` unwrap — any new caller feeding it user-supplied numbers must `!is.finite()`-guard first.
- 2026-07-17/18 (M27, M33): **unwrapping `ssm_draws()` displacement intervals.** Non-contrast rows wrap each CI endpoint independently into [0, 360) (only the *contrast* row is realigned onto the estimate's branch, `R/ssm_bootstrap.R` `if (contrast)`), so a seam-straddling interval has `d_lci > d_uci`. Where the estimate is within a half-turn of BOTH bounds (contrast rows, coverage checks) shift each endpoint by its signed circular distance, `((bound - est + 180) %% 360) - 180` — never by the estimate's branch offset, which inverts the ribbon. But that clamps bounds into (-180, 180] of the estimate, so it cannot represent a stored interval whose CCW arc exceeds 180°: a 337° "displacement unknown" interval renders as a 23° INVERTED band. For arbitrary non-contrast intervals anchor the lower bound — `lo <- branch - ((est - lci) %% 360); hi <- lo + ssm_arc_span(lci, uci)`. `check()` catches neither; the figure just renders wrong.
- 2026-07-18 (M33): `results$Occasion` is a CHARACTER column and `details$occasions` is the only ordering authority — a discrete ggplot2 scale re-sorts it alphabetically, flipping a `T10`/`T2` pair and silently reversing the time axis. Factor against `details$occasions` in any occasions plot. Also: the prior-PR-comments review lens is a permanent clean no-op in this repo (every merged PR has 0 review comments; review happens through cairn), so its "no findings" carries no evidential weight here.
- 2026-07-18 (M33): rendering a new plot and LOOKING at it catches what no data-level test does — an ungrouped series drawn in a hue that encodes nothing, and a `scale_shape_manual` legend key rendered invisible from a pale inherited group colour (fix: `guides(shape = guide_legend(override.aes = list(color = "black")))`). Budget one render-and-inspect pass per new figure; data-level fences and the vdiffr baseline both pass a figure that reads wrong.
- 2026-07-18 (M35): to extract a shared helper out of a prior milestone's code and still use that milestone's suite as an UNTOUCHED fence, parameterize the helper by the varying column's *name* rather than renaming the column to a neutral one — the old path keeps `Occasion`, the new path carries the caller's `wave`, zero test edits, and the fence claim stays literal.
- 2026-07-18 (M34): agent-written file content can carry leaked tool-call scaffolding — a `Write` of a vignette shipped literal `</content>`/`</invoke>` lines at the tail, and `devtools::check()`, `check_pkgdown()`, AND a 9-job CI matrix all passed, because pandoc emits unmatched closing tags as raw HTML and browsers drop them. No toolchain gate sees this class of defect. After writing any doc file wholesale, check its tail bytes (`tail -6 f | od -c`).
- 2026-07-18 (M34): `ssm_analyze_long()` derives occasion order from the column TYPE — first-appearance `unique()` for character, `levels(droplevels())` for a factor — and `factor()` sorts levels alphabetically, so a default-factor `wave` yields `T1, T10, T2`. The roxygen hedges this correctly; prose flattening it into "occasions appear in the order they were supplied" is FALSE. Never document occasion order as unconditionally temporal without naming the factor branch.
- 2026-07-18 (M36): a legend key whose break exists but whose GLYPH is missing is a `show.legend` problem, not a data-presence problem — under the default (`NA`) a layer claims only the breaks its own data contains, so `scale_*_manual(limits=, drop = FALSE)` keeps the label while the symbol slot renders as a `zeroGrob`. `show.legend = TRUE` on the existing layer is the whole fix; `override.aes` does not reach a keyless break, and presence layers (zero-row, `alpha = 0`) work but are inert machinery inviting deletion. Test by reading key grobs: each key is a gTree holding a `legend.key.rect` plus a `points` grob or a `zeroGrob`; count EVERY `points` grob per key (not the first) to catch two layers overdrawing one key.
- 2026-07-18 (M37): a CUSTOM optional aesthetic mapped to a discrete column silently destroys a layer — `add_group()` builds `group` from EVERY discrete column when the caller maps none (only `label`/`PANEL` exempt, no extension point), so a character `order` aes put each row in its own group and `GeomPath` returned a `zeroGrob`: nothing drawn, no error, and alphabetical `T1`/`T10`/`T2` misordering — exactly what the aesthetic existed to prevent. Every test used a NUMERIC order column, where it works. Prefer `geom_path()` parity (data row order + `group`); ordering belongs in the wrapper that knows the true order. Render-and-inspect again (M33): an arrow terminating AT a point marker is drawn UNDER it and invisible — draw an arrowed path last, head sized to clear the marker.
- 2026-07-18 (M38): patching a `ViewScale`'s `breaks` after the parent coord builds it desynchronizes it from anything the *scale* pairs positionally with its own breaks — a scale carrying explicit `labels` aborts the build on the length mismatch, and blanking an appended entry by index into `NULL` labels fabricates literal `NA` labels. Ask the scale to label only its own breaks and add the appended entry separately. Neither path is reachable through the package's own API, so the suite and a 15-figure vignette sweep passed over both.
- 2026-07-18 (M38): calibrating a label-collision rule from break spacing calibrates the wrong quantity — collisions track rendered label *width*, so an arithmetic estimate of the safe threshold was off by half and only rendering the candidate outcomes at each ratio exposed it (`1.00`/`1.10` printing as `1.0010`). Render the candidates before writing the rule.
- 2026-07-19 (M39): `stringWidth()`/`stringHeight()` take a character vector, so `as.character()` on a plotmath label measures its deparsed source (`"gamma^2"`) not the rendered glyph — a plate several times too wide. Measure text-with-possible-expressions via `grobWidth`/`grobHeight` on a `textGrob` built from the label itself; it handles strings and expressions alike.
- 2026-07-19 (M39): match a target grob in a rendered tree by BOTH structural position (inside the named `axis` gtable) AND content (label set) — content alone plated spoke labels that happened to read like amplitudes, and the theta guide is traversed first so a first-match short-circuit selects the wrong one. A vdiffr baseline that skips on CI fences nothing on CI; assert size/offset structurally too.
- 2026-07-19 (M40, extended M42): **an `Extraction:` status may claim only what each channel actually saw.** A human attestation of an OLD record does not transfer to a NEW page built from it — authoring a source note is itself a fresh extraction — so M40 claimed "verified twice and independently" while eight Appendix-A values rested on `pdftotext` alone. And two channels are not two *witnesses*: on an Acrobat "Paper Capture" OCR scan the text layer is OCR output of the same page image, so it corroborates nothing — on Browne (1982) it dropped every display equation, leaving the image the only channel (M42-D1). Check `pdfinfo` Producer before claiming independence. The gitignored shelf is LIVE, so re-check absence claims at merge, not at write.
- 2026-07-19 (M41): a source note's "nothing in the repo uses this" claim must be grepped for the source's FORMULAS, not its citation — M41 wrote that nothing computes Browne & Cudeck's RMSEA equations while `R/cpm_fit.R:1049,1011-1028` had implemented eqs. 13/14 all along, UNATTRIBUTED, so the citation grep saw nothing and the page shipped a falsehood plus an incomplete `Traces to`. An unattributed implementation is invisible to the grep that would find it. Cross-reference only pages on disk.
