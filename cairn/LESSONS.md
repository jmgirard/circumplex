- 2026-07-13 (M19): when seeding parallel simulation cells by a formula, index the level, never the raw value — `seed_base = ... + 1e6*match(cfg) + 1e3*N` collided the (boundary,N=2000) and (interior,N=1000) cells because `1e3*2000 == 1e6*1 + 1e3*1000`; use `1e3*match(N, all_ns)` so the config and N terms can't alias. The diff-bug reviewer caught it; marginal per-cell coverage stayed unbiased (each cell has its own chol transform) so the conclusion held, but cross-cell independence was silently lost. Verify seed formulas produce distinct streams across ALL cell pairs, not just within a cell.
- 2026-07-13 (M19): the CPM free-scaling family ALWAYS fits a unit-diagonal correlation matrix (`cpm_fit` cormat path requires it; the data path uses `cor()`); there is no covariance-input path. So the only well-posed coverage-oracle truth is a circumplex CORRELATION P(γ) with σ_pop=1 — σ̂ is a free nuisance that equals 1 only at perfect fit. Don't try to simulate "non-unit σ" truths for free-family coverage; cor(X) discards the variances. An analytic-only coverage run (engine fit + `cpm_analytic_se`, no per-fit bootstrap) is session-runnable (~3.5 min for 12 cells × 500 reps), unlike the bootstrap-laden diag stages — extend `devel/m4-coverage-oracle.R` with `CPM_COV_FREE_ONLY=1` to run just the free stage.
- 2026-07-13 (M19): a caution/guardrail that ships behind a design deferral (M18-D3's placeholder unconditional free caution) often ships UNTESTED — grep for a test of the exact wording before assuming coverage. The free bordered σ-Hessian is far more singular-prone than the diag one (NA SE in ~52–55% of N=250 fits vs ~0 for diag), so free-family small-N analytic CIs are often simply undefined — a distinct failure mode from mis-coverage, worth conditioning oracle stats on (count SE-failures separately, don't drop silently).

Not re-transcribed here — cited from legacy.
- 2026-07-12 (M8): behaviour-preserving SEM refactors are fenced by two byte-pinned guardrails — the `exp_strict_*` syntax snapshots (`test-ssm_sem_syntax.R`) and the `summary()` label strings (tabs/casing) — so DRY extraction there is safe to verify by "existing suite stays green". The single/multi-group emitters in `ssm_sem_syntax.R` are NOT a shared extraction (plain vs `c()`-vector cross-group labels); don't try to unify them.
- 2026-07-12 (M9): vectorizing `sem_estimate()`'s per-draw transform loop needed NO re-pins — keep the tested scalar `sem_ssm_transform()` as the reference and pin the matrix pass to it row-by-row (incl. the §5.5 flat/zero-amplitude NA semantics); `rowMeans`/matmul FP reorder stays within existing tolerances. `sem_pop()`-composing `make_pop_2g()` was bit-identical (same op sequence), so re-recording the coverage rds is a deterministic no-op — verify by `identical()` instead of an expensive stochastic rerun.
- 2026-07-12 (M11): mechanical test-fixture rewrites must be validated with `devtools::check()`, not just `devtools::test()`/`load_all()`. Consolidating inline populations into a `sem_canonical_pop()` helper removed a block's `a`/`cc` locals it still used to rebuild `lambda1`; `test()`/`test_file()` under `load_all()` **masked** the `object 'a' not found` (an earlier block's `a` leaked into scope), and only the clean-env R CMD `check()` caught it. Also: the four SSM boundary invariants were already covered at the bootstrap/montecarlo/ci_accuracy/SEM entry points — the real gaps were the *correlation* path's flat and pole corners; audit before writing a "new" boundary suite (`cairn/boundary-coverage.md` is the standing matrix).
- 2026-07-12 (M12): when DRY-extracting a Label/Group/Measure builder, swapping `cbind(Label, Group, Measure, df)` (vectors + df) for `cbind(labels_df, df)` (df + df) is byte-identical in R ≥ 4.0 — same column names, character (not factor) types, and row names — provided the helper builds its data.frame with `stringsAsFactors = FALSE`. Verify by `identical()` on both the default and non-default (contrast) row-name cases, not just value equality; the byte-pinned end-to-end snapshot/label tests are the oracle (no separate statistical oracle needed for a behaviour-preserving label refactor).
- 2026-07-12 (M10): `cairn_validate.py`'s ISO-date check flags any `\d+/\d+/\d+` token as a malformed date — writing a `check()` result as "0/0/0" in a tracking file trips it. Write "0 errors / 0 warnings / 0 notes" (spaces around slashes) instead. Also: when a milestone Goal names a function family but the enumerated Scope/Tasks list specific sites, grep the whole family first — the plan's site list drifts (post-merge line shifts) and can silently omit members (M10 missed `ssm_analyze()`'s own validators; the two-lens review caught it).
- 2026-07-12 (M14): to make a hardcoded package listing self-maintaining, enumerate datasets at runtime via `utils::data(package = "circumplex")$results[, "Item"]`, load each into a `new.env()` and `inherits()`-filter by class (drops example data) — `check()` stays clean without declaring `utils` (base pkg, already used elsewhere). When refactoring a `cat(...)`-based printer, reproduce its default `sep = " "` leading-space artifact (`cat(c(header, lines))`), and prove the byte-format with a snapshot that changes only the intended line; pair it with a data-derived structural test (M13 teeth rule) so the two oracles disagree only on real drift.
- 2026-07-12 (M13): a regression-guard test that **re-types** the production expression instead of calling the production code path has NO teeth — the review (F1) caught a "CPM angle-CI oracle" whose end-to-end fixture never straddled the pole, so a linearized `cpm_fit.R:1119` passed it. Prove a guard bites by breaking the guarded line (`assignInNamespace` a linearized `quantile.circumplex_radian`) and confirming red. To force a deterministic 0/360 straddle through `cpm_fit()`: put a *non-reference* item exactly on the pole, sample raw data via `cpm_implied_cor()`+`chol()`+`rnorm()` (seeded, base-R, no MASS), and assert the reported CI **wraps** (`Angle_lci > Angle_uci`) — a linear quantile yields a ~357° non-wrapped span instead. Such a bootstrap+optimization test is deterministic given the seed and (large-margin wrap) robust enough to run in CI under `skip_on_cran()` alone; Windows CI green confirmed no BLAS flip.
- 2026-07-12 (M16): running the suite from bare `Rscript` silently SKIPS `skip_on_cran()` tests (NOT_CRAN unset) — set `NOT_CRAN=true` to exercise them; `testthat::test_dir/test_file` default `stop_on_failure=TRUE` (throws "Test failures" and aborts your aggregation — pass `stop_on_failure=FALSE`); and the results data.frame's `failed` column EXCLUDES `error` — a test that errors shows `failed=0`, so always sum `error` too. Also: `aw2009` is too small for `ssm_ci_accuracy()` (pooled n < #scales → "Too few observations" error); use a `jz2017` fit for any diagnostic-based test.
- 2026-07-12 (M16): a name collision with a loop variable can corrupt a display-only surface while leaving the computation correct — a constant `cert_k <- 0.35` added atop `ssm_ci_accuracy()` was clobbered by the loop's existing `cert_k <- rowSums(...)` (certified count), so the summary echo printed garbage while the actual certification (a separate `ssm_certified()` call) stayed right; behavioral tests all passed and only a snapshot caught it. Grep the function for the name before introducing a constant, and snapshot the echo surfaces, not just the computed numbers. When rewriting live-rendered vignette prose after a rule change, RE-RUN the exact vignette config and rewrite from the actual new output — the narrative claims (which profile is certified, whether a caution fires) flip with the rule and cannot be edited by guesswork.
- 2026-07-13 (M18): when a milestone changes the *semantics* of a function's return value (not just its diff), the bug lives in the CONSUMERS, not the diff — `cpm_fit()`'s `matrices$Phat` went correlation→covariance under `scaling="free"`, and `ssm_ci_accuracy(cpm=)` silently embedded the non-unit diagonal into a correlation population. The diff-bug (Opus) reviewer cleared the consumer by checking only its internal unit-fit path; the blame-history lens caught the reachable user-supplied `cpm=` path it missed. Lesson: on any return-value-semantics change, grep every consumer of that field and guard the ones that assumed the old invariant; the multi-lens fan-out earns its cost exactly here (one lens's blind spot is another's catch). Guard, don't silently coerce — refuse the unsupported combination with a clear message + regression test.
- 2026-07-13 (M18): OpenMx's ML fit for `type="cov"` applies an internal (N-1)/N rescale to the observed matrix. For the diag-constrained CPM family that SHIFTS the optimum (pre-multiply the observed by N/(N-1) to match), but the free-scaling family is closed under rescaling, so the factor is absorbed ENTIRELY into σ̂ — `diag(Σ_mx) = VarRatio·(N-1)/N` while θ/ζ/β/F̂ stay invariant. When cross-checking free-scaling σ̂² against OpenMx, apply the (N-1)/N factor (it doubles as a clean rescale-equivariance confirmation); CSOLNP's optimizer tail also means σ̂²/F̂ agree only to ~5e-4, not 1e-8.
- 2026-07-16 (M21): a standalone `rmarkdown::render()` of a vignette runs against the *installed* package, not the dev tree — a dev-line vignette (here: `fit_structure()`, absent from installed 1.2.0.9999) fails spuriously and the failure points at an innocent chunk far from your edit. `devtools::check()` is the authoritative vignette build (it installs the source package into a temp lib first); don't chase standalone-render failures before comparing `packageVersion()` against DESCRIPTION.
- 2026-07-16 (M20): the 0/360 pole's float label is platform- and path-dependent — R-level `%%` clamps the fmod edge to exact 0 (macOS) while the C++ `modu` estimate path yields exact 2π, and cross-platform last-ulp libm variation can leave a pole residue a few ulp wide; so any pole-snap window must be ≥ a few ulp of 2π (M20: 16*eps ≈ 4 ulp — a 2*eps window is thinner than ONE ulp of 2π and only ever catches bit-exact 2π), and estimate-path boundary assertions follow G2's either-label rule — reserve `expect_identical(…, 360)` for value-level-snapped endpoint contracts, never for values that ride through libm trig.
- 2026-07-12 (M15): a "display consistency" change to a diagnostic has more surfaces than the obvious print method — for `ssm_ci_accuracy()` the certification-conditional contrast figure lived on FOUR surfaces (`coverage$Coverage_conditional`, the `verdict` Class, `guardrail$Cert_rate`, AND `plot.circumplex_ci_accuracy()`'s "Displacement (certified)" panel). The plan enumerated three; the Fable review (RR02) caught the plot as a fourth "beyond the brief". Grep every consumer of the column/parameter being resemanticised before scoping. Key design split that generalises: *measured quantities stay in the returned object; only interpretive/presentation surfaces (verdict/print/summary/plot) follow the print method's stance* — so relabel the verdict `Parameter` (`"d_conditional"`→`"d"`) rather than silently changing its contents (a greppable, self-describing change beats a silent value swap under an unchanged label). Existing snapshot/plot fixtures were profile-only, so contrast behaviour had NO guard until this milestone added a contrast print snapshot + a data-level (`plot(res)$data`) panel-exclusion test — check fixture coverage of the branch you're changing, don't assume the snapshot covers it.
