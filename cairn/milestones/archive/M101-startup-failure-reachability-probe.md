# M101: Find out whether a run that never starts reaches the master-red alert

**Status:** done (2026-08-21, PR #130 https://github.com/jmgirard/circumplex/pull/130)

**Goal:** Establish by deliberate experiment whether a push run of a watched workflow that fails to start on the default branch delivers a `workflow_run` event `.github/workflows/master-red-alert.yaml` can match, and record the measured answer where the alert's readers will find it.

**Outcome:** A public probe repo, `jmgirard/gha-startup-failure-probe`, carrying a byte-identical copy of the alert, drove two broken watched workflows on its default branch: YAML that does not parse (run 32540432744) and a file that parses and declares `name:` but fails schema validation, a job with no `runs-on` (run 32540622138). Both concluded `failure` with zero jobs — neither produced `startup_failure`, so M99's widening still has no measured instance — and NEITHER produced an alert run or issue, while a positive control (same path, valid file, exit 1) was matched and opened issue #1. GitHub reported each broken run's `name` as the file PATH and the control's as its declared name, which makes name resolution the leading explanation, but name and file validity varied together in every cell, so it stands as a correlation. The alert's header comment now records this per case with full run URLs and states explicitly that an absent alert run does NOT distinguish a never-delivered event from one delivered and filtered out by `workflows:` — a `workflows:`-side fix is not ruled out. The alert's `on:` block and job `if:` are byte-identical to master; every change on the branch is comment text or tracking. The repo is kept public so the cited run URLs stay resolvable and open items (b) and (c) can be driven.

**Decisions:** none milestone-local; nothing promoted to DECISIONS.md.
