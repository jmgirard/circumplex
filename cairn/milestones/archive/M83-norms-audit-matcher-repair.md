# M83: Make the norms-audit abort matcher accept correct sites

**Status:** done (2026-08-14, PR #111 https://github.com/jmgirard/circumplex/pull/111)

**Goal:** The test machinery that enumerates and matches `data-raw/audit-norms.R`'s abort sites accepts the message each declared site actually raises, and flags only genuine denied abort spellings.

**Outcome:** `norms_audit_stopifnot_stem()` returns `list(stem, truncated)` and the matcher applies its length floor only where R did not truncate — the floor tracked the key while the value compared against it is R's first deparsed line, so a braced `function(el) {...}` condition made a correct site fail its own matcher (stem 37 against an effective floor of 40). Truncation is recognised only in R's own shape, space + four dots + verdict (`NORMS_AUDIT_VERDICT`). Denylist rule (iii) skips non-value operands via `NON_VALUE_OPERANDS` (`$`/`@` operand 3, `for`'s index), while `calls_denied_field()` catches a call *through* such a field as rule (i). New `norms_audit_acceptance_matrix()` and `norms_audit_expected_offdiag()` give the cross-site matrix one derivation, verified by two mutants each shown vacuous on the other's fixture. `expect_abort_at_site()` refuses a non-`norms_audit_matcher` by name. Test machinery only; no runtime surface.

**Decisions:** AC2's no-floor-when-truncated rule keeps a measured residual leak, pinned rather than closed — `stopifnot({ ... })` yields the one-character stem `{`, and message-level matching cannot separate two conditions whose first deparsed lines agree; the cross-site matrix is what stands behind discrimination there.
