# M159: Selection guards for the scales argument

**Status:** done (2026-10-18, PR #194 https://github.com/jmgirard/circumplex/pull/194)

**Goal:** The exported functions that take `scales` refuse a selection that reaches one column twice, holds a position below 1, or names a column whose name occurs twice in the data, with an error that names the cause.

**Outcome:** Three internal helpers in `R/utils.R`: `check_scales_selection(data, scales)` (positions below 1 after truncation, a name repeated in the column names it indexes, one column selected twice; NA, absent names and past-last numbers pass through to the caller), its position half `check_scales_positions()`, and `check_scales_labels()` for label-only paths. Called by `ssm_analyze()`, `ssm_analyze_long()`, `ssm_score()`, `ssm_parameters_id()`, `ssm_sem()`, `cpm_fit()` (data path; labels on the `cormat` path, with a hint to pass unique `scales`), `fit_structure()` (judged on the raw matrix it indexes), `norm_standardize()`, `ssm_growth_data()` (M158's guard moved onto the helper, same messages), `ssm_sem_parameters()` and `ssm_sem_syntax()`. `ssm_analyze()` refuses a character `occasions` block naming a repeated column (NA names skipped). `ssm_growth_data()` refuses a list-column `id` (POSIXlt exempt). A number selecting a column whose name repeats stays accepted. Refusals are errors with no deprecation cycle (plan question set). Tests in `tests/testthat/test-scales-selection.R`, with an enumeration test over exports with a `scales` formal; help pages and NEWS ("Breaking changes") updated.

**Decisions:** none milestone-local. `stop(call. = FALSE)` over `cli::cli_abort()` (cli is no dependency). `self_standardize()` and `items` arguments left out on GP2 grounds (row "Selection guards without angles").
