# M96: Say something when master goes red

**Status:** done (2026-08-19, PR #125 https://github.com/jmgirard/circumplex/pull/125)

**Goal:** Open a GitHub issue automatically when a push run of `R-CMD-check.yaml` or `test-coverage.yaml` on the default branch concludes failure.

**Outcome:** `.github/workflows/master-red-alert.yaml` — a `workflow_run` alert gated on failure + push + default branch, `permissions: issues: write` only, a `concurrency:` group per watched workflow. Dedupe is per workflow by issue title behind a `master-red` label created if absent before the search; every GitHub call is non-fatal, so a refused label list or create posts an unlabeled issue with a `::warning::` rather than aborting the alert. The issue body reports four `workflow_run` payload fields carried in through the step `env:`. Two hand-run audits, named in `PROFILE.md`'s consistency-gate slot: `tools/check-master-red-alert.R` (trigger, whole-`if:`, effective permissions, `env:` mapping, watched siblings' `name:`, label ordering, no installs, no step-level `if:`) and `tools/master-red-alert-dryrun.R` (the workflow's own shell body against five stubbed fixtures, comparing the text every issue call produces against a committed template). `PROFILE.md`'s two master-watch bullets merged, with M93's absent-run rule and M95's no-verdict rule each scoped to their own watch.
