# M157: Input guards for ssm_growth_data()

**Status:** done (2026-10-17, PR #192 https://github.com/jmgirard/circumplex/pull/192)

**Goal:** `ssm_growth_data()` refuses the four kinds of input that today give a wrong long table with no error: duplicated referenced column names, `scales` selecting the id or time column, infinite time values, and repeated person-by-time rows.

**Outcome:** Four guards in `R/ssm_growth_data.R`, all `stop(call. = FALSE)` calls placed before the unchanged scoring and stacking. (1) A column name that `id`, `time` or a character `scales` entry refers to and that occurs more than once in `names(data)` is refused, the names read after `as.data.frame()` so a blank matrix name renamed `V<n>` is judged too; an unreferenced duplicate, a numeric scale reaching a duplicated name, and an `NA` scale name (left to the scorer's "undefined columns") pass this check. (2) `scales` reaching the `id` or `time` column is refused, numbers resolved as `seq_along(data)[scales]`, so a non-integer double truncates as R does. (3) `Inf`/`-Inf` time is refused after the NA check. (4) Repeated rows are found by `duplicated()` on `factor(id)` and `as.numeric(time)`, the values the output holds: ids equal to 15 significant digits (`0.1 + 0.2`, `0.3`) are one person, and time is compared exactly. Ten test blocks in `tests/testthat/test-ssm_growth_data.R`, each refusal asserting the message that names its argument and offending column or value; the branch-point blocks run unedited. The help page and the NEWS refusal list name all four. Deferred to the "Growth id and scales edge inputs" row: double ids that merge at different times, and names repeated inside `scales`.

**Decisions:** none milestone-local. The repeated-row refusal rests on GP2's wrong-object clause (the `data` contract is one row per person per time point), chosen over a warning at the plan gate.

**Review:** three-lens fan-out, 15 findings. Fixed on the branch: blank matrix names becoming a duplicate `V<n>` after conversion, which let `id` bind the wrong column or gave a false "selects the `id` column" (diff-bug #1, #2); the `NA` scale-name message (#3); an unanchored "`time` 1" test pattern (#4); undocumented exact time comparison (blame #2); a roxygen line wrap (#5). Follow-up: the help page states the 15-digit id merge as current behavior, noted on the edge-inputs row (blame #1). Rejected: the deferred cases (planned), `is.infinite()` after `anyNA()` (false), the dataset test using the scorer's values (planned, AC5's evidence), two NEWS wraps (style). Criteria audit at plan (8 findings) and claim audit at implement (25 claims, 3 corrected) ran with fresh readers. Check 0/0/0; CI green on all six checks.
