# M151: Growth input helpers, the long table and the formula builder

**Status:** done (2026-09-24, PR #186 https://github.com/jmgirard/circumplex/pull/186)

**Goal:** Ship `ssm_growth_data()` and `ssm_growth_formula()`. A reader then builds the stacked long table and pastes the validated joint model's fit call for glmmTMB, nlme or brms without composing either.

**Outcome:** `ssm_growth_data(data, scales, angles, id, time)` scores each row through `ssm_parameters_id(id = NULL)` and stacks `e`, `x`, `y` into a four-column long table, rows ordered by input row then `dv`. It refuses absent, reserved (`dv`, `value`), equal, non-numeric or `NA` id and time columns, and muffles only the scorer's undefined-displacement warning. `ssm_growth_formula(engine, time, id)` returns the one oracle-validated joint model as formula objects (glmmTMB `formula`/`dispformula`, nlme `fixed`/`random`/`weights`, brms `formula`/`sigma`), backticking non-syntactic names so a name never reads as formula syntax. Its print shows the complete fit call, the nlme one with `na.action = na.omit`, and the `coef`/`vcov` or `draws` extraction lines. `tests/testthat/fixtures/growth-fixef.rds` (generator `data-raw/growth-fixef.R`, glmmTMB 1.1.15, TMB 1.9.25) holds the glmmTMB fit on both growth datasets. An nlme parity test matches it to 1.3e-14 on fixed effects and 6.9e-6 of the largest covariance entry against a 1e-4 bound. nlme entered Suggests (D-064) and the four CI install allowlists. NEWS and the pkgdown "Growth Model Functions" group updated.

**Decisions:** none milestone-local. D-064 (plan gate) governs the three helpers and nlme.
